## 实现与边界

- `app/src/main/platform/win/windows.ts`：调用时才加载 DLL；查询线程临时使用 Per-Monitor V2，结束后恢复原上下文。主进程自己的窗口默认完全排除。窗口快照包含物理边界、DPI 感知方式、最小化/最大化/全屏/系统隐藏状态、按钮来源，以及是否可以站立、是否参与遮挡。窗口标题不采集。
- Z 序使用 `GetTopWindow`、`GetWindow(GW_HWNDNEXT)`；与 `EnumWindows` 的句柄快照对照，不假设回调顺序。遇到环或缺少仍存在的窗口最多重试三次，之后明确报错。[Windows 对 GetWindow 的 Z 序及循环风险说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow)。
- 不支持 DPI 或只感知系统 DPI 的程序优先使用 `WM_GETTITLEBARINFOEX` 的屏幕坐标，不沿用 M0 对 DWM 偏移与宽高一起放大的公式。消息有 8 ms 超时；取得的矩形不夹边，明显不在窗口外框内则拒绝作为按钮。无法可靠定位这类窗口的按钮时不提供可站顶边。[TITLEBARINFOEX 的坐标和按钮索引](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-titlebarinfoex)。这条路径仍需用另一进程的 UI Automation 真实核对。
- Per-Monitor 窗口同样优先使用标题栏绝对坐标。第五轮确认 WinUI 记事本的 DWM 区域左端多留空白，所以不把它当首选；标题栏接口无有效数据时才读取 DWM 相对按钮坐标并加物理外框原点。自绘标题栏两种来源都无效时保守预留右侧 160 DIP，并标记 `fallback`。这些退路没有通用准确性保证，核对脚本仍要求与实际按钮一致。[DWM 对按钮边界的定义](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。
- 第六轮发现浏览器自绘按钮与标准标题栏尺寸不同。Per-Monitor 窗口现在以标题栏/DWM 作为定位提示，通过 `WM_NCHITTEST` 二分实际按钮联合边界，标记 `hit-test`；超时立即停止继续发送消息，布局不能定位时保留原来源及其已声明限制。相对矩形缓存最多 1 秒；移动只平移，尺寸、DPI、进程及提示布局改变时重读，不可站立/关闭时清理缓存。同尺寸动态布局最多等待 1 秒重新校正。算法假定相邻标题栏按钮构成连续联合矩形，非标准离散形状不保证精确。[系统命中返回值](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest)。
- 工具窗口、太小窗口、最大化或全屏窗口不站猫，但有实体时仍遮挡下层。沿用已测试的 M0 策略：分层且鼠标穿透的窗口、全局 alpha 为零的窗口不参与遮挡。逐像素透明、可见的穿透装饰和圆角仍不作精确形状判断，按 M0 的限制记录，不能宣称通用透明遮挡已解决。
- `window-ledges/compute.ts`：纯计算，不依赖 Electron 或系统；只使用猫所在屏幕的**物理工作区**及缩放，输出工作区内的局部 CSS 坐标。裁剪跨屏部分并减掉按钮、上层窗口。默认排除短于 8 DIP 的碎线；调用方可传实际最短宽度。猫的身体上方空间和落脚条件归 #115，线段存在不等于猫一定能站上去。
- `window-ledges/tracker.ts`：地板模式无定时器、无系统读取；窗口模式没有猫站顶边时每秒采样一次，有猫站顶边时按 33 ms 延时采样。实际间隔包含查询耗时及调度延迟，**33 ms 不是实测延迟保证**。输出位移及真实采样间隔、窗口不可站立通知；查询失败清掉旧顶边并报告错误，下一轮重试。`refresh()` 供 #116 的屏幕变化和调试触发使用。

## 真机核对方法

从工作树的 `app/` 运行：

```powershell
# 只读环境和窗口信息，不移动、不测性能；可直接运行。
npx electron scripts/verify-window-ledges-entry.js --inspect

# 每台机器、每种显示配置、每轮都先征得用户明确同意。
npx electron scripts/verify-window-ledges-entry.js --approved --measure

# 有多个老程序窗口时可以指定一个；必须是真正的 DPI 不感知窗口。
npx electron scripts/verify-window-ledges-entry.js --approved --measure --legacy=<窗口句柄>

```

脚本要求记事本、实际浏览器、资源管理器和一个 DPI 不感知老程序的窗口存在；缺少任何一个都会失败，不跳过。浏览器同时核对进程名称，避免误选同样使用 Chromium 窗口类的 Codex。另创建独立的 DPI 不感知 Legacy 窗口、遮挡窗口和两种透明层用于回归，Legacy 测试窗口不冒充真实老程序应用。测试暂时移动、调整大小、最小化和最大化窗口，结束后恢复原位置、大小及状态；只关闭本轮创建的测试窗口，不关闭用户应用。

`verify-window-caption.ps1` 在单独的 PowerShell 进程中通过 UI Automation 获取最小化、最大化和关闭按钮，按公开名称及 AutomationId 识别，不使用被测算法的按钮边界。应用不支持的最小化/最大化按钮按 UI Automation WindowPattern 确认，不能强求不存在的按钮。原生预测矩形必须同时通过左右边缘、上下边缘和宽度比较，误差不超过 2 物理像素；旧算法右端即使夹住，左边缘及宽度仍会失败。

辅助功能核对同时读取窗口树及右上角实际屏幕位置的元素；统一 Per-Monitor V2 物理坐标，排除其他进程、标签页关闭按钮并按矩形去重。第九轮资源管理器通过这条路径取得真实按钮，没有触发鼠标悬停，因此移除了未使用的悬停备选。

不暴露标题栏辅助功能的应用使用 issue 允许的截图路径：独立向实际窗口查询 `WM_NCHITTEST`，扫描系统报告的按钮命中范围，不输入预测的按钮矩形；单独的 PowerShell 进程以物理外框尺寸通过 `PrintWindow` 直接捕获目标窗口，整个窗口仅存在内存，磁盘只保存按钮区域及 16 DIP 横向上下文，不保存标题和正文，也不经过 Electron 缩略图缩放。[PrintWindow 的窗口捕获说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow)。纯色截图、无法找到关闭按钮、消息超时、截图大小不匹配都会失败。原始参考坐标及截图留待逐张视觉核对，不能仅凭脚本创建了 PNG 就宣称按钮位置通过。[WM_NCHITTEST 对屏幕坐标和按钮返回值的定义](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest)。

第九轮旧式 IExpress 的 `PrintWindow` 按钮区域为纯色，不能作为证据。现在纯色时再用物理屏幕截图：核对窗口已临时置顶，在截取区域四角和中心通过 `WindowFromPoint`/`GetAncestor` 确认属于目标窗口，裁剪不超出 DWM 可见外框。被遮挡或再次纯色仍失败；输出明确标记图像来源。这个退路尚待下一轮实测。

移动代理测量是 Win32 移动命令到主进程顶边更新回调，包含查询及调度耗时；不是鼠标拖动到屏幕呈现，也不包含尚未接入的桌面层和 IPC。遮挡采用已知置于目标上方的真实窗口，并同时核对 Z 序和顶边缺口。

性能测量分别对地板、窗口空闲、窗口占用各预热 1 秒并测量 30 秒，保留一个真实可站立的标准测试窗口，避免恢复应用后只测空桌面。统计核对进程累计 CPU，分别列单核和按逻辑处理器数量归一化后的整机百分比，整机平均要求低于 2%。窗口创建及应用核对不计入测量区间；测量前后检查其他 Electron/素材工厂竞争进程。这个数值只代表本模块所在的核对进程，完整应用 CPU 须等 #116 接线以后另测。

结果默认写到忽略的 `app/out/window-ledges/`。可将本次真实的部分结果保存到 `docs/验证报告/M4-窗口顶边-证据/`，但必须标明未完成及失败点，不能替代整轮验收。提交的 JSON 不含用户窗口标题、正文或本机绝对路径；截图只保留逐张确认过的按钮区域。失败不能用上一轮的成功文件替代。
