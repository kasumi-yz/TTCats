## 1. 测试方法

- **交互测试**：`npm run interaction-test`（在 `app/` 里运行，先 `npm run build`）。
  - 启动正式应用（测试猫咪包、临时存档目录），在猫下面放一个独立进程的"探针窗口"。
  - 用 `SendInput` 发系统级鼠标键盘事件，和真人操作走同一条路。
  - 猫的位置来自桌面层的画面报告，点击位置按猫咪包里真实的点击遮罩计算：所有帧、两种朝向都要满足。
  - 每次点击前后都核对四件事：光标还在脚本放的位置、Ctrl 没被别人按下、幽灵模式符合预期、桌面层仍在探针窗口上面。任何一项不对都算"被打断"，该场景自动重做，最多 3 次（PR #44 审查要求）。
  - 测试期间把地板纵深调到 2%，让三只猫站在几乎同一条线上，方便摆出"两只猫重叠"；其余设置都是默认值。
- **性能**：`npm run perf:app`。启动正式应用和 3 只测试猫，口径与 M0-A 相同：
  - 正常播放、全部隐藏、全屏时自动隐藏三种状态，各过渡 15 秒、测 300 秒，约每秒采样一次。
  - 统计应用所有进程的 CPU（整机百分比之和）和私有内存；全屏窗口是独立进程，不计入。
  - 每 15 秒检查一次独占：不能有别的会话在跑 Electron 或素材工厂。
  - 目标：CPU 平均 < 2%，私有内存峰值 < 700MB。
- 原始数据在 [`M1-验收-素材/`](M1-验收-素材/)。

### 首轮失败记录

首轮正式运行 25 项通过、2 项失败（[原始数据](M1-验收-素材/interaction-2880x1800-150pct-首轮.json)）：

- **右键菜单不抢焦点**：脚本用系统菜单窗口（`#32768`）判断菜单有没有弹出。但 Electron 在 Windows 上用自己的窗口画菜单，所以一直判断成"没弹出"。之后按 Esc 也没关掉菜单。
- **防卡死：从猫身上移到空白处**：上一项留下的菜单还开着，占住了鼠标，桌面层收不到"鼠标已离开猫"。

两项都是测试脚本的问题。修正：改为旁听 Electron 菜单自己的显示和关闭事件；Esc 关不掉时像真人一样点回输入框；无论结果如何都确保菜单关掉。没有改应用代码，也没有放宽阈值。复测 27 项全部通过。

## 5. 验收中发现并修复的 bug：NVIDIA 游戏悬浮层让猫一直躲起来

**现象**：在这台笔记本上，猫一直不出现。重启电脑后也一样。

**原因**：桌面层用 Windows 的 `SHQueryUserNotificationState` 判断"前台有没有全屏程序"，有就把猫藏起来（D10）。NVIDIA App 的游戏内悬浮层（`NVIDIA Overlay.exe`）开机就常驻，有两个铺满屏幕的隐形窗口，Windows 因此一直报告"忙碌"（状态 2）。实测结束这个进程的瞬间，状态变回正常（5）；它被自动拉起后，又变回 2。装了 NVIDIA App 的电脑都可能这样。

**修复**（`app/src/main/platform/win/index.ts`）：

- Windows 报告"忙碌"时，再核对**前台窗口是否真的盖满它所在的整块屏幕**。没盖满就不算全屏。
- 前台是桌面、任务栏，或白名单里的程序（目前只有 `NVIDIA Overlay.exe`），也不算全屏。
- 独占全屏的游戏（状态 3）和演示模式（状态 4）照旧直接隐藏。

**验证**：

- 单元测试覆盖了悬浮层误报、白名单、桌面和任务栏、副屏全屏、独占全屏和演示模式。
- 真机上，NVIDIA 悬浮层开着时判断为"不是全屏"；打开真正盖满屏幕的全屏窗口时判断为"全屏"，关掉后恢复。
- 性能测试的"全屏时自动隐藏"阶段也在真机上验证了这一点。

这项修改超出了 #29 列出的"允许修改的目录"，按 #29"验收时发现的 bug：小的直接修，并在 PR 里说明"处理。

## 6. 性能（笔记本，独占）

2026-10-02，笔记本 2880×1800 150%。整个测试期间独占检查都通过（每 15 秒一次）。应用设置为优先用低功耗显卡（这台机器有 AMD Radeon 780M 核显和 RTX 4060 独显）。[汇总数据](M1-验收-素材/perf-app-summary-2880x1800-150pct.json)。

| 状态 | 采样数 | CPU 平均 / 峰值（整机%） | 私有内存 平均 / 峰值（MB） | 工作集平均（MB） | 是否达标 |
|---|---|---|---|---|---|
| 正常播放 | 276 | **1.54** / 3.32 | 591 / **687** | 784 | ✅ |
| 全部隐藏 | 278 | 0.54 / 1.01 | 601 / 603 | 808 | ✅ |
| 全屏时自动隐藏 | 279 | 0.30 / 0.34 | 601 / 603 | 804 | ✅ |

按进程拆开（正常播放，平均）：

| 进程 | CPU % | 私有内存 MB |
|---|---|---|
| 主进程 | 0.13 | 120 |
| GPU 进程 | 0.60 | 391 |
| 桌面层渲染进程 | 0.80 | 69 |
| 工具进程 | 0.00 | 11 |

需要注意的地方：

- **内存余量很小**：正常播放时私有内存峰值 687MB，离 700MB 目标只差 13MB。300 秒里有 6 次采样超过 650MB，是短暂的尖峰；平均从前 30 秒的 567MB 升到最后 30 秒的 603MB，之后隐藏阶段稳定在 601～603MB。大头是 GPU 进程（约 390MB，全屏透明画布和视频解码缓冲）。
- 换成真实猫片段（分辨率更高）以后，内存很可能超过 700MB。建议豆豆的片段接入时重测，到时如果超标，再讨论怎么取舍。
- 隐藏以后内存没有降下来（601MB），说明已经解码的片段缓存没有释放。CPU 降到 0.5% 以下，符合"隐藏时不画"。
- 因为没做"连续运行一整天"（第 4 节），**长时间运行时内存会不会持续增长，这次没有验证**。
