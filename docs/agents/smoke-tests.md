# 写冒烟测试

冒烟测试（`app/e2e/smoke.spec.ts`）在每个 PR 的 Windows CI 里跑，是最慢的一步。新增或修改冒烟测试时遵守下面几条，免得越跑越慢。

## 时长规矩

- **能快进就快进，不按真实时间干等。** 和游戏时间有关的（勿扰到期、开机静默、计时类状态），用调试台快进（`debug/advanceClock`，或调试台的快进按钮）。
- **单项一般不超过 20 秒。** 确实要更久的，在测试里写注释说明为什么不能快进。
- **每种"按真实时间走"的机制，全套冒烟只留一项真等。** 比如"没有操作时程序按真实时间自己推进"只由"定时推进"那项验证，其他测试一律快进。
- **整套冒烟的目标是 3 分钟以内**（以 CI"冒烟测试（Windows）"那一步的用时为准）。超过时，新增冒烟测试的 PR 要先把已有的测试压缩回 3 分钟以内。

## 测试猫在冒烟里走得快

冒烟的启动器（`app/e2e/launch.js`）把测试猫走路、奔跑片段的速度放大 4 倍（环境变量 `TTCATS_SMOKE_WALK_SPEEDUP`）。`app/test-content/` 本身不变，交互测试和性能测试仍用原来的速度。

所以冒烟里等猫入场、出场、让开、走到某处，一般几秒内就会完成。等待上限（`timeout`）按这个速度设，不要再为慢猫留几十秒的余量。
