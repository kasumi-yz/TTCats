# 挑片台与素材工厂的接口

对应 #129，为 #104 的挑片台（ReviewStation）和 #105 的素材工厂 v1 先统一接口。此 PR 只定义格式和类型，窗口、按钮、文件读写和素材工厂接入分别在后续功能 PR 中实现。

## 输入：候选与原始记录

挑片台读取素材库里的 `manifest.json`，按 `CandidateManifestSchema` 校验，按猫和 `clip.name` 分组。视频路径相对于该清单所在目录。`candidateId` 只在同一猫、同一片段名下唯一，所以不能只凭它作为全库文件标识；主进程给每个候选签发独立的 `candidateKey`。

旧候选无需改文件。新增的可选字段是：

```json
{
  "assessment": {
    "score": 89.5,
    "reasons": ["首尾轮廓接近", "仍需检查镜像后花纹"]
  }
}
```

分数范围为 0～100，越高越好，必须带非空原因。没有此字段时显示“尚无自动评分”。分数不能自动改变 `status`，也不能把人工确认设为通过。

豆豆已有的 `factory/<任务>/finalize/manifest.json` 配套记录如下，主进程可据此恢复可编辑草稿：

- 同一任务的 `ingest.json`：原始猫名、源视频路径和 SHA-256、尺寸、帧数、帧率。
- `matte/000000.png` 等：保留原始尺寸的逐帧透明画面，供标注。
- `suggest/suggestion.json` 和已有 `confirmation.json`：建议/人工确认的裁剪、循环、落脚锚点与步速。
- `finalize/export-log.json` 的 `options`：`ClipOptions`，包括原始逐帧关键点、声音起始帧和既有导出参数。

工厂 v1 继续提供同样的记录。读取顺序为：已保存的合法 `review-result.json` 优先，否则用已有确认记录，再用建议记录生成草稿。只要不是已保存的人为确认结果，草稿的 `accepted` 一律为 false，即使旧清单为 accepted，也要由用户在这次挑选里主动确认。没有源记录的候选仍能并排播放，但显示不能编辑的原因；不能用已对齐的成品点位冒充原始坐标。

## 输出：review-result.json

结果保存在**输入候选 `manifest.json` 旁边**的 `review-result.json`，不进入仓库或游戏存档。共享定义是 `app/src/shared/schemas/review-result.ts`，生成文件是 `schemas/review-result.schema.json`。

| 字段                             | 含义                                                                 |
| -------------------------------- | -------------------------------------------------------------------- |
| `schemaVersion`                  | 当前版本固定为 1，未知版本必须报错                                   |
| `cat`、`candidateId`             | 与输入清单一致，使用稳定 id，不使用中文显示名                        |
| `candidateManifestSha256`        | 加载时输入清单**原始字节**的 SHA-256，小写十六进制 64 位             |
| `source`                         | 源视频 SHA-256 与 ingest 后的 `width`、`height`、`fps`、`frameCount` |
| `kind`                           | 与清单的 `clip.kind` 一致，决定实际导出区间                          |
| `selection.trimStart`、`trimEnd` | 原始帧号，裁剪区间 `[start, end)`                                    |
| `selection.loopStart`、`loopEnd` | 原始帧号，循环区间 `[start, end)`，必须在裁剪区间里                  |
| `selection.footAnchors`          | 原始每一帧的落脚锚点，数量必须等于 `source.frameCount`               |
| `selection.keypoints`            | `nose`、`scruff` 等关键点的原始逐帧坐标，看不见的帧是 null           |
| `selection.speed`                | 原始画面的像素/秒，与 `Suggestion.speed` 相同，非负                  |
| `selection.soundStartFrame`      | 可选，原始帧号，必须在实际导出区间里；省略表示从成品第 0 帧开始      |
| `accepted`                       | 人主动确认合格才为 true；false 可以保存，但不能正式导出              |
| `note`                           | 人工备注，允许空字符串                                               |
| `manualSeconds`                  | 人实际花费的秒数，非负有限数，不包含自动处理耗时                     |

所有帧号从 **0** 算起。循环片段导出 `[loopStart, loopEnd)`，其他片段导出 `[trimStart, trimEnd)`。循环片段的声音起始帧要落在循环区间内，只落在裁剪区间内还不够。

所有坐标都是 **ingest 后原始画面**的像素，原点在左上角，要求 `0 ≤ x < source.width`、`0 ≤ y < source.height`。裁剪仅截取时间；这里不存成品编码像素、桌面显示像素或镜像坐标。编辑用的帧保留原始尺寸；界面显示缩放时必须逆变换点击坐标，标注镜像画面时还必须逆镜像，不能把右边画面上的点直接写回。

例如有 100 帧的源视频：裁剪 `[10, 90)`，循环 `[20, 80)`，声音标在原始第 25 帧。工厂导出循环片段 60 帧，成品的声音起始帧为 `25 - 20 = 5`。锚点和关键点在结果文件中仍各有 100 项，工厂导出时才切出 60 项。

## 校验与 Python 对接

TypeScript 使用 `validateReviewResult(data, { cat, candidateId })`，传入当前加载清单的身份。它先校验完整 schema，再核对猫和候选 id；错误会包含猫、候选、字段路径和中文原因。

JSON Schema 能校验版本、类型、必填字段、未知字段、静态上下限和哈希写法。与已有 `ClipSchema` 一样，Zod 的 `superRefine` **不会变成跨字段 JSON Schema 约束**。Python 在 `jsonschema` 校验后还必须检查：

1. `0 ≤ trimStart < trimEnd ≤ source.frameCount`。
2. `trimStart ≤ loopStart < loopEnd ≤ trimEnd`。
3. 每条轨迹长度等于 `source.frameCount`；锚点不能为 null，关键点可以为 null。
4. 所有非 null 点在原始画面范围内。
5. 声音起始帧在由 `kind` 决定的实际导出区间内。

两端还必须核对实际文件：猫/id/kind 与清单相符；清单字节哈希未变；`source` 与 `ingest.json` 一致；源视频实际字节哈希与 `source.sha256` 一致；所需抠图帧存在且尺寸/数量正确。仅满足结果文件内部约束，不能证明它仍对应当前素材。

工厂读取结果后的映射如下，不增加第二套人工确认机制：

| 挑片台字段                                     | 素材工厂 v0 字段                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------ |
| `trimStart`、`trimEnd`、`loopStart`、`loopEnd` | `Suggestion` 的 `trim_start`、`trim_end`、`loop_start`、`loop_end` |
| `footAnchors`、`speed`                         | `Suggestion.foot_anchors`、`speed`                                 |
| `accepted`、`note`、`manualSeconds`            | `Confirmation.accepted`、`notes`、`manual_seconds`                 |
| `keypoints`、`soundStartFrame`                 | `ClipOptions.keypoints`、`sound_start_frame`                       |

`Suggestion.cat` 继续使用 `ingest.json` 的猫名；`ClipOptions.cat_id` 使用清单里的稳定猫 id。原建议的 `loop_error`、`warnings` 等不由人伪造，继续从建议记录读取。其他导出选项来自原 `export-log.json`，不能从渲染进程接受任意工厂命令或原始文件路径。

复用现有 confirm/finalize 的校验、落脚锚点对齐、关键点坐标变换、声音帧偏移及解码 alpha 遮罩验证。改变所选帧以后，按手册重算显示高度；保留原素材的比例依据，不能直接继承旧裁剪的 `display_height` 或写死豆豆参数。#104 只接入结果读取；批处理、初筛等仍由 #105 实现。

正式导出写入新的独立目录，记录输入候选与结果的哈希，保留原候选、原始记录和历史失败证据。返回新清单和视频 URL，不覆盖用户正在并排对照的原候选。

## 开发面板接口

类型和通道名在 `app/src/shared/review-station.ts`。`PanelsBridge.reviewStation` 可选：开发模式提供，安装版不提供。#104 可以在主进程模块内实现专用 preload，接口 PR 不修改现有生产 preload，也不注册实际 IPC。调试台用 `openWindow()` 打开挑片台；命令入口由 #104 实现。

| 方法                                                     | 主进程负责的动作                                            |
| -------------------------------------------------------- | ----------------------------------------------------------- |
| `openWindow()`                                           | 打开/聚焦挑片台，只允许开发模式                             |
| `getLibrary()`                                           | 返回上次选择的素材库清单，没有则为 null                     |
| `chooseLibrary()`                                        | 弹出目录选择器、记住用户选择；取消为 null，当前库不变       |
| `loadCandidate(candidateKey)`                            | 校验配套记录，返回原始帧参数草稿与已有结果修订              |
| `getSourceFrame(candidateKey, frame)`                    | 验证整数帧号范围，返回该候选原始尺寸 PNG 的受限 URL         |
| `chooseBackground()`                                     | 弹出图片选择器，返回用户选定桌面截图的受限 URL，取消为 null |
| `saveResult({ candidateKey, expectedRevision, result })` | 校验、锁定、保存结果，返回新修订的哈希                      |
| `exportCandidate(candidateKey, expectedRevision)`        | 核对已保存的确切修订且 accepted，再让工厂正式导出           |

主进程只接受自己的开发窗口发来的请求。开发开关必须同时保护窗口、IPC 和资源读取；不能只隐藏按钮。资源 URL 只允许读取已授权候选的视频、原始帧和用户选定的背景图，限制在真实路径之内，拒绝目录穿越、符号链接越界和未经选择的文件。切换素材库时旧 `candidateKey` 和旧资源授权失效。IPC 参数作为 unknown 在主进程校验，不能把 TypeScript 类型当成运行时校验。

旧清单里如果缺源记录或有损坏文件，`ReviewCandidatePreview.editProblem` 说明原因；整个素材库里单个错误放进 `ReviewLibrary.problems`，不能让其他合法候选都消失。方法失败时 Promise 拒绝并给出中文错误；取消选择不算错误。

## 写入、并发与版本

`revision` 是当前 `review-result.json` 原始字节的 SHA-256，初次保存前为 null。保存、导出都必须在同一候选的排他锁中重新读取文件并核对修订；不能仅靠进程内队列处理多个程序/工厂进程。主进程和工厂共同使用候选目录内的 `.review-lock`（排他创建），锁内记录所有者信息，finally 仅释放自己的锁；遇到遗留锁要明确报错，让人核实后清理，不能按猜测的时间自动删除仍在使用的锁。

锁内核对 `expectedRevision`、清单/源文件身份，写同目录临时文件，写完再原子替换结果文件；成功后保留最近 5 份旧结果备份。失败时原结果仍可用，恢复文件时也必须通过 schema 校验。素材库路径偏好由主进程以版本化记录保存，使用同样的原子写入和备份要求。

版本 1 是首次交付，没有旧版挑选结果需要迁移。今后引入不兼容修改时提高版本，提供明确迁移；本次不加空的迁移字段或未来阶段占位代码。
