# TTCats 设计方案

> 来源：2026-09-30 的 grilling 讨论（已根据 Codex review 修订），用户已批准。
> 术语以 `CONTEXT.md` 为准，架构决策见 `docs/adr/`。
> 标有 **【待 M0 验证】** 的内容，要等 M0 实测后才能最终确定。
> 当前进度看 GitHub issue：第一阶段 PRD 以及它下面的子 issue。

## 总览

把三只真实的家猫（豆豆、库啵、麻将）做成桌面宠物，分五个阶段完成：
1. 桌宠本体（Windows）
2. 猫与猫之间的互动 + 养成
3. 类似 QQ 宠物的世界、小游戏和商店
4. 移植到 Mac
5. 换猫

约束：
- 用户没有编程经验，全部采用 vibe coding，并且同时开多个 Claude Code 和 ChatGPT/Codex 会话并行开发（规则见 `AGENTS.md`）。
- 美术全部由其他 AI 生成。
- 完全重写。旧项目 DeskCats 只沿用了三只猫本身的描述，没有参考它的程序架构。

设备：
- 开发和性能验收用笔记本：RTX 4060 + 780M。
- 素材工厂跑在台式机上：RTX 5090 D v2，24GB 显存。

## 一、已确认的决定

### 基础

- **D1 给谁用**：自己和亲友小范围使用。
  - Windows 安装包用 NSIS 制作，不做代码签名。
  - 通过 GitHub Releases 自动更新。
  - 首发只有简体中文；界面文字集中放在一处。
  - 第五阶段的"换猫"是这样实现的：由制作者做好猫咪包，朋友拿到后导入。
- **D2 技术选型**：Electron + TypeScript（ADR-0001）。具体工具：
  - 构建：electron-vite
  - 面板界面：React
  - 猫的渲染：PixiJS
  - 数据校验：zod
  - 测试：Vitest
  - 打包：electron-builder
  - 调用系统接口：koffi
- **D3 美术风格**：第一、二阶段用写实风，第三阶段用卡通风，两种形象共用同一份数据。
  - 片段格式是带透明通道的 VP9 WebM，用 PixiJS 当视频纹理来渲染 **【待 M0 验证，ADR-0002】**。
  - 备选方案是把片段预先解码成一帧帧图片，但要先算清内存：按 24fps、每段 2 秒、2 倍尺寸估算，三只猫同时播放大约占 80MB。
- **D8 视频生成**：先比较，再选主力；生成器可以随时替换（ADR-0006）。
  - 参加比较的有三方：本地 MiniMax H3、本地 Wan 2.2、一个在线工具。
  - 必须写清楚具体用的模型文件和工作流版本。
  - ComfyUI 官方的 Wan 2.2 首尾帧工作流用的是 14B 的 I2V 模型（分高噪声和低噪声两个文件），24GB 显存需要用量化版。官方页面上的 5B 版本不带首尾帧工作流。
  - H3 的许可证把美国、欧盟、英国、韩国列为排除地区，使用前要确认自己不在这些地区。
- **D22 仓库保持公开**：
  - 真实照片和 AI 生成的原始视频不放进仓库，存在台式机的素材库里，并同步到网盘备份。
  - 仓库里只放代码、文档和处理好的片段。

### 第一阶段

- **D4 活动范围**：有地板模式和窗口模式两种，可以切换。
  - **地板**：有纵深感。猫用侧面走路的动画斜着走，按远近缩放，最远处是 85%，最近处是 100%。离得远的猫会被离得近的猫挡住。
  - **跳跃**：拆成"蹲下蓄力 → 腾空 → 落地"三段，中间的飞行轨迹由程序计算。
  - **窗口模式的规则**：
    - 猫不会站在标题栏按钮的位置。
    - 窗口顶边被其他窗口挡住的那一段，猫不会站上去。
    - 最小化、最大化或全屏的窗口，猫不会站上去。
    - 窗口移动时，站在上面的猫跟着一起走。
    - 窗口被快速拖动或晃动、被关掉、被最小化时，猫会掉下来。
    - 用户把猫拖到窗口顶边附近松手，猫会站到窗口上。
  - 窗口模式放在第一阶段最后做；在 M0 先做一个小范围验证。
- **D5 互动**：
  - **单击**：猫按自己的性格做出反应；连续点太多次，猫会走开。
  - **右键**：打开这只猫的菜单，可以叫它过来、让它睡觉、暂时隐藏它、查看资料卡。
  - **托盘菜单**：点猫的名字就能召唤它。
  - **撸猫**：不用按鼠标键，1.5 秒内在猫身上来回划 3 次以上就算撸猫。猫会播放呼噜片段，身边冒出爱心；撸的时间超过它的耐心，它就走开。
  - **拎起来放下**：拖动猫时它悬在空中，松手后落下，最后落地。不做"甩飞"的效果。
  - **鼠标靠近**：猫按性格决定是凑过来还是躲开。
  - 逗猫棒和激光笔放到第二阶段。
- **D6 事件**：用通用的事件系统，每个事件写成一份配置，内容包括触发条件、冷却时间、参与的猫和分几步进行。
  - **随机**：猫咪跑酷、追飞虫。
  - **按时间**：早上第一次开机时说早安；到了真实的喂饭时间（可以设置），提醒你喂真猫；深夜时猫会犯困。
  - **看你的状态**：只读取系统的空闲时间，据此判断你离开了、你回来了、你坐太久了。你离开时猫会睡觉，你回来时猫会迎接你，坐太久时会提醒你休息（这个提醒可以关掉）。
  - **纪念日和节日**：每只猫的生日、到家纪念日、各种节日，只用粒子特效、地板装饰和气泡来表现，因为写实风的猫没办法"戴"东西。这部分放在第一阶段靠后做。
- **D7 动画规则**（ADR-0002）：
  - **基础姿势**：站、坐、睡。**连接姿势**：悬空、伏低、腾空。腾空能不能和悬空共用，要在 M0 确认。
  - 每个姿势都有一张姿势帧，每只猫大约 5～6 张，全部用真实照片生成，光线、角度、大小保持一致，背景用纯色，而且和猫毛的颜色反差要大。
  - 每个片段都从某个姿势开始、在某个姿势结束，用 AI 工具的首尾帧功能生成。
  - **生成时的硬性要求**：镜头固定不动；纯色背景；光线方向保持一致。
  - **打断时怎么衔接【待 M0 验证】**：交叉淡化、硬切加小特效遮挡、专门做过渡片段，三种方式都实测一遍再选。
  - 每只猫要做 22 个片段，每种先做 1 个版本。如果"被拎起"需要专门的过渡片段，再额外加几个。
  - **可选片段**：比如朝镜头走、背对镜头走，或者某个动作的更多版本。有就用，没有也不影响运行。
  - 片段分批制作，每个都记进素材档案。
  - **防止看腻**：待机时长随机；播放速度在 0.9～1.1 倍之间浮动；同一个动作不连续出现两次；用一两周后，哪个看腻了就给哪个补新版本。
- **D10 防打扰**：
  - **全屏时**：前台有全屏游戏、视频或 PPT 时，猫自动隐藏（Windows 上用 `SHQueryUserNotificationState` 判断），退出全屏后猫从屏幕边上走回来。
  - **截图和会议里是否显示猫**：做成开关，默认不显示（`setContentProtection`）。这个开关**只在 Windows 10 2004 以上有效，而且只对使用系统标准截屏接口的软件有效**。常用软件会逐个实测，结果写在设置说明里，不做绝对保证。想要带猫的图，可以用"拍照"功能。
  - **幽灵模式**：按住 Ctrl 时，猫变成半透明，鼠标可以穿过它们；松开后再保持 2 秒。另外，如果你在猫旁边连续点击，猫会自己走开。
  - **活跃度**：五档，分别是安静、慵懒、自然、活泼、闹腾，默认"自然"。
  - **勿扰模式**：可以设定持续时间。另外有一键隐藏的全局快捷键；开机启动时静默，不弹窗、不抢焦点、不出声。
- **D11 声音**：
  - 先用通用猫叫（CC0 音效库或 AI 生成），三只猫各选一种风格：麻将的嗓门大，豆豆的叫声短而安静，库啵的叫声软。以后换成自家猫的真实录音。
  - 呼噜声默认打开；喵叫默认打开，但音量偏低。
  - 安静时段默认是 23:00～8:00；安静时段和勿扰模式下都不出声。
  - 每段声音从片段的哪一帧开始播放，在挑片台上标注。
- **D12 多显示器**：猫只待在一块屏幕上，默认是主屏，可以更换。程序底层按"每块屏幕一个桌面层"来设计。插拔显示器、缩放比例变化、远程软件创建的虚拟显示器消失时，猫都会回到主屏，并从屏幕边上走进来。
- **D13 其他细节**：
  - 可以任选显示哪几只猫（0～3 只）。被隐藏的猫从屏幕边上走出去，重新显示时再走回来。
  - 程序启动时猫依次入场，顺序是麻将最先、豆豆最后。
  - 缩放范围 50%～200%，100% 时猫站着大约 150 像素高，三只猫之间保持相对大小。地板的纵深可以调节。
  - **设置窗口**包括：显示哪几只猫、活动模式、活跃度、大小、在哪块屏幕、声音、截图里是否显示猫、勿扰、快捷键、开机启动、喂饭时间、生日和到家日、久坐提醒、自动更新。
  - **托盘菜单**包括：召唤、显示或隐藏某只猫、切换模式、勿扰、截图里是否显示猫、拍照、设置、退出。
  - **第一次使用**时，由猫自己冒气泡提示操作方法，每条提示只出现一次，而且在对应的情境下才出现。
  - **崩溃恢复**：
    - 如果只是桌面层崩溃，就自动重新加载；5 分钟内最多重试 3 次。
    - 重试超过次数就进入安全模式：加载上一份正常的存档，停用出问题的猫咪包，并提示你导出诊断信息。
    - 如果整个程序退出了，不会自己重启，要等下次开机时自动启动。
  - **诊断信息导出**：把日志、设置、版本号、系统信息打包，方便交给 AI 排查问题。
  - 卸载时会询问要不要删除存档。
  - 数据存放在 `%APPDATA%\TTCats`。
  - 开发调试台用隐藏快捷键打开，可以播放任意片段、触发任意事件、快进时间、查看每只猫的状态。
  - **性能目标**（在笔记本上测）：CPU 低于 2%，内存低于 700MB（按私有内存算，接近任务管理器里显示的数；M0-A 实测后由 300MB 调整），不会一直唤醒独显，隐藏时停止绘制。

### 第二阶段

- **D14 猫与猫的互动**（ADR-0008）：
  - 以拼接式互动为基础，每只猫额外做 3 个社交片段：伸头闻、用头拱、舔对方。需要对准位置的地方（比如鼻子），在挑片台上标注关键点。
  - 另做 3～5 个名场面。名场面的首帧和尾帧由两只猫的姿势帧拼接而成。播放时两只猫先走到位，然后切换成名场面，播完再切回两只单独的猫。
  - 某个互动如果没有对应的名场面，就自动退回拼接式。名场面要先做一次"双猫验证"。
- **D15 养成的核心**：
  - **需求**有三项：饱腹，下降的节奏和真实的喂饭时间对齐；心情，撸猫、玩耍、梳毛、吃零食会让它上升，被戳太多、饿了、被冷落会让它下降；精力，由猫自己管理，累了就去睡。
  - **亲密度**只增不减，共 1～10 级，每升一级会解锁新的行为、事件或名场面。
  - 这些数值只通过猫的行为、头顶的气泡和面板来表现。
- **D16 不设惩罚**（ADR-0007）：猫不会生病、不会离家出走、不会死。各种"猫不在"情况的处理如下：

| 情况 | 算不算离线 | 需求怎么变化 | 会不会触发久别重逢 | 错过的定时事件 |
|---|---|---|---|---|
| 退出程序或关机 | 算 | 按真实时间计算，最多算 12 小时 | 离开 4 小时以上才触发 | 不补发 |
| 系统睡眠或锁屏 | 算 | 同上 | 同上；如果和当天第一次的早安赶在一起，合并成一次 | 不补发 |
| 用户隐藏了某只猫 | 这只猫算 | 同上 | 隐藏超过 4 小时，重新显示时才触发 | 不补发 |
| 全屏时被自动隐藏 | 不算 | 照常变化 | 不触发 | 不补发；只有喂饭提醒例外，会在 1 小时内补发一次 |
| 开着勿扰模式 | 不算 | 照常变化 | 不触发 | 同上 |

  不做防作弊，用户改系统时间也没关系。
- **D17 功能**：
  - **喂食和零食**：饭碗画在地板上，麻将会去抢别的猫的饭。每只猫多做 1 个"吃饭"片段，饭碗也要画进这个片段的首帧和尾帧里。
  - **梳毛**：复用呼噜片段。
  - **逗猫棒和激光笔**：猫按性格反应。麻将最积极，会抢在最前面；库啵追几步就停下；豆豆大多数时候只是盯着看，偶尔慢慢地、准准地扑一下。
  - **猫咪之家窗口**：显示状态、图鉴、相册（用拍照功能拍的照片）和猫咪日记（每天自动记下几件趣事）。
  - 家具放到第三阶段。
- **D18 其他细节**：
  - 第二阶段不引入货币，零食每天补 3 份。
  - 亲密度的增长速度：麻将最快，库啵中等，豆豆最慢。每一级具体解锁什么，写第二阶段 PRD 时再定。
  - **8 种拼接式互动**：闻鼻子打招呼、挨着睡、舔毛、抢位置、短距离追逐、跟着走、一起盯着看、抢食。
  - **互动的频率**跟真实关系对应：麻将和库啵之间最常互动；麻将对豆豆主要是抢位置和抢食；豆豆和库啵之间主要是打招呼。
  - **麻将的强势**只表现为插队、抢位置、抢食和短距离追逐，不会哈气，不会打架，也不会让谁害怕它。
  - **首批名场面**：麻将和库啵蜷在一起睡；麻将给库啵舔头；麻将把豆豆挤走。
  - 第二阶段总共要新增 15 个片段。

### 第三到五阶段

这几个阶段现在只记录需求，**不写任何占位代码**。等到做的时候，靠存档迁移机制和"数据驱动猫"的设计把功能加进来。

- **D19 第三阶段**：
  - **外出**：派猫去打工、上学、旅游或探险。猫从桌面上走出去，过一段时间带着小鱼干、物品和一张卡通明信片回来，日记里也会多一条记录。
  - 另外还有：小游戏（每个小游戏是一个独立模块，有统一的接口）、商店、小鱼干货币、家具。
  - 这些都放在世界窗口里，用卡通风格。
- **D20 Mac**：
  - 用户有 Mac，或者能借到一台。
  - 不付费签名，写一份图文说明，教朋友手动放行。
  - 默认只打包 Apple M 系列芯片的版本。
  - 第三阶段的内容要不要一起移植到 Mac，到时候再决定。
- **D21 换猫**（ADR-0005）：
  - 用 `.ttcat` 猫咪包，可以导入任意数量的猫，自由组合显示，但同时最多显示 5 只。
  - 安装包里自带豆豆、库啵、麻将。
  - 来自不同猫咪包的猫，彼此的关系默认是"普通友好"。
  - 新猫的性格从几种预设里选一个，再用滑块微调。

## 二、三只猫

| 猫 | 外观 | 体型 | 性格 |
|---|---|---|---|
| 豆豆 | 金渐层，毛很蓬松，绿眼睛，戴浅象牙色的窄项圈，项圈上有一个小金色挂件 | 身长和麻将差不多，体型更圆 | 稳重从容，不爱动，独立，不容易被打扰 |
| 库啵 | 美短起司，身上有虎斑 | 三只里身长最短，也最胖 | 被动型黏人，喜欢安静地靠过来，很少和别的猫争抢 |
| 麻将 | 暹罗，脸、耳朵、爪子、尾巴是深色 | 身长和豆豆差不多，体型更修长 | 活泼，强势，主动黏人，爱抢关注 |

- **关系**：
  - 麻将和库啵最亲，经常贴在一起。
  - 麻将和豆豆最不亲。麻将常去抢豆豆的位置，豆豆要么不理它，要么慢慢让开，几乎不会正面冲突。
  - 豆豆和库啵是普通朋友。库啵偶尔会靠过来，豆豆一般会容忍。
- **做素材时要注意**：
  - 豆豆的毛最难抠，所以美术验证就拿它来测，背景用蓝色系；它的项圈挂件是重点质检项。
  - 麻将身上的深色部位不能被当成阴影抠掉。
  - 库啵的虎斑，要在挑片台上把原版和镜像版放在一起对比：不能接受镜像的，就把最常用的 5 个片段左右各做一版。

## 三、架构

### 状态由谁管（ADR-0004）

- **需要存档的状态**只由**主进程**修改，包括需求、亲密度、设置、事件冷却、各种时间戳和存档本身。结算按真实经过的时间来算，不按帧数累加。
- **画面状态**由**桌面层**管理，包括位置、当前片段、行为计划。这部分可以随时丢弃，重启后让猫重新入场就行。
- **窗口之间怎么通信**：面板和桌面层只向主进程发送两种消息：命令（比如喂食、改设置）和事实（比如"豆豆被撸了 3 秒"）。主进程更新状态后，把快照推送给各个窗口。
- **core 是纯 TypeScript，分成两部分**：
  - `core/game`：在主进程里运行。
  - `core/stage`：在桌面层里运行。

### 运行时结构

```
主进程：窗口管理、托盘、core/game（唯一的状态管理者）、存档、自动更新、日志和诊断、崩溃恢复
  └ platform/win（koffi）：窗口列表、全屏状态、Ctrl 键和鼠标按键、DPI 与多显示器
        │ IPC（命令 / 事实 / 状态快照）
桌面层（透明、置顶、默认鼠标穿透、不抢焦点）
  ├ core/stage：行为选择、姿势网络路径规划、事件执行、表面、跳跃和下落
  └ 渲染（PixiJS）：视频纹理、镜像和远近缩放、按纵深排序、阴影、气泡和粒子、点击遮罩、片段衔接
面板（React）：设置、猫咪之家（第二阶段）、调试台、挑片台（开发模式，M1 之后）
```

### 鼠标交互的安全规则（ADR-0003）

- 鼠标落在猫的不透明像素上（依据每一帧的点击遮罩判断）时，桌面层才临时接收鼠标事件；其他时候鼠标一律穿过去。
- **防卡死**：只要鼠标不在猫身上、也没有在拖动，必须在 200ms 内恢复鼠标穿透。
- 桌面层不抢焦点：点猫、拖猫、撸猫以后，用户原来正在打字的窗口仍然保持焦点 **【待 M0 验证】**。

## 五、验收方法

- **自动测试**：
  - `npm test`：覆盖 core/game（需求变化、离线结算、各种"猫不在"情况、存档迁移）和 core/stage（行为选择、姿势路径、事件）。
  - `npm run validate:content`：检查内容文件是否符合格式。
  - 素材工厂的 pytest。
- **真实桌面交互测试脚本**：M0 做出来以后，每个里程碑都要重新跑一遍。截图里能看到猫，不代表猫下面的窗口能正常接收点击。
- **性能脚本**：测量口径和 M0 的 A 线相同，每次发版前都要跑。跑的时候，同一台机器上不能有别的会话在运行 Electron 或素材工厂。
- **人工验收**：每个里程碑配一份中文的《验收清单》，配合调试台逐项检查。
- **M0 的通过标准**：
  - 豆豆放在深色和浅色壁纸上都看不出残留的色边。
  - 整条动作链没有明显的跳位或重影。
  - 走路时脚不打滑。
  - 你本人确认"这就是豆豆"。
  - 性能和交互测试都通过；没通过的项，已经讨论过怎么取舍。
