# 桌面层：透明置顶窗口，默认让鼠标穿过，按每帧的点击遮罩判断是否点中猫

猫生活在一个透明、置顶的窗口里，这个窗口覆盖整块屏幕的工作区，而不是给每只猫各开一个小窗口。这样一来，猫之间的互动、按纵深决定谁挡住谁、超出猫本身范围的动作，都能在同一个画面里完成。

具体规则：

- 窗口默认让鼠标穿过。只有当鼠标落在猫的不透明像素上（按片段每一帧的点击遮罩判断）时，窗口才临时接收鼠标事件。
- 防卡死：只要鼠标既不在猫身上、也没有在拖动，就必须在 200ms 内恢复"鼠标穿过"。
- 窗口不抢焦点，以免打断用户正在打字的窗口。

## Considered Options

- **每只猫一个小窗口**（Shimeji 那种做法）：挡住的桌面更少。但猫之间的互动要在多个窗口之间同步，频繁移动窗口也容易卡顿。

## Consequences

- Electron 的"鼠标穿过"开关只能对整个窗口生效；只把猫的轮廓当作可点击区域，要靠我们自己做判断。
- M0-A 用真实桌面交互测试脚本验证通过（笔记本 2880×1800 150%，23 项全部通过）：鼠标快速移到猫身上后立刻点击、拖动时鼠标移出猫的范围、拖动时按住 Ctrl、两只猫重叠、焦点没有被抢走、防卡死（最慢 63ms，包括桌面层卡死的情况）。台式机上 3440×1440 100% 和 2560×1440 100% 两种配置还要补测（D23）；如果不通过，再修改本 ADR。
- 截图里能看到猫，不代表下面的窗口还能正常接收点击。每个里程碑都要按 D23 的实测分工重跑真实桌面交互测试。
- **实现时必须这样做**（M0-A 实测得出）：
  - 防卡死由**主进程**兜底：鼠标在猫身上时，桌面层定期续一个短租约；主进程同时检查光标位置和左键状态，租约过期就恢复鼠标穿过。不能只靠桌面层，因为桌面层可能卡死。
  - 不能用 `mouseleave` 判断鼠标离开了猫。
  - 拖动用 pointer capture，主进程也检查左键状态，防止松手事件丢失。
  - 已经拎起来的猫，按 Ctrl 不会被扔下。
- 鼠标移到猫身上后几毫秒内的点击可能会丢（真人操作不会遇到）。
