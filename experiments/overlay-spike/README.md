# M0-A 桌面层验证小样（overlay-spike）

对应 issue #2。这是**一次性原型**，用来实测 ADR-0002、0003、0004 里还没定下来的做法，不是正式代码，也不会被 `app/` 引用。
测量结果和结论写在 [`docs/验证报告/M0-A-渲染与交互.md`](../../docs/验证报告/M0-A-渲染与交互.md)。

用到的技术和正式工程一致：Electron 44 + TypeScript + PixiJS 8（视频纹理）+ koffi（调用 Windows API）。

## 需要什么

- Windows 10 2004 以上（实测环境是 Windows 11），真实桌面（远程桌面也可以，但性能数据不算数）
- Node.js 24 以上
- `ffmpeg` 在 PATH 里（生成测试片段、截图测试和录屏要用；winget 装的 Gyan.FFmpeg 就行）

## 运行

```bash
cd experiments/overlay-spike
npm install
npm start
```

第一次运行时会自动下载 Electron 本体（约 100MB）。`npm start` 之前会自动生成测试片段（如果 `assets/clips/` 里还没有）并编译到 `dist/`。

启动后屏幕右下方会出现 3 只"假猫"（用椭圆拼成的合成形状，不是真猫），任务栏托盘里有一个橙色圆点图标，右键可以：

- 切换**衔接方式**：交叉淡化（150ms）/ 硬切 + 小特效 / 专门的过渡片段
- **打断全部猫**：让所有猫立刻换姿势，看衔接效果
- **截图里显示猫**：不勾选时开启截图隐身（默认）
- **隐藏全部猫**、**显示调试信息**（左上角：帧率、饱腹值、片段切换耗时）、**退出**

可以直接用鼠标：点猫（换姿势）、拖猫（拎起来，猫变成悬空姿势，松手落地）、按住 Ctrl（幽灵模式：猫变半透明，鼠标穿过；松开后保持 2 秒）。

`npm start -- --layout=demo` 会把三只猫并排摆开，每只用一种衔接方式，每 2.6 秒自动打断一次。

### 桌面层的命令行参数

| 参数 | 作用 |
|---|---|
| `--layout=normal\|demo\|test` | 猫的摆放方式 |
| `--mode=crossfade\|hardcut\|transition` | 默认衔接方式 |
| `--gpu=low-power\|default\|high-performance` | 用哪块显卡。默认 `low-power`（强制核显） |
| `--fps=30` | 限制画面刷新率（默认跟显示器一样） |
| `--preload=all\|lazy` | `all`：所有片段都预加载；`lazy`：只加载正在播和接下来要播的 |
| `--res=1` | 画布分辨率倍数（默认跟系统缩放一致） |
| `--no-hud` | 不显示调试信息 |
| `--bare` | 只开一个空白透明窗口（测 Electron 本身的开销） |

## 自动测试脚本

| 命令 | 做什么 | 大约多久 |
|---|---|---|
| `npm run interaction-test` | 真实桌面交互测试：用 `SendInput` 发系统级鼠标、键盘事件，检查点击判定、拖动、Ctrl 幽灵模式、两猫重叠、焦点（含记事本：只在测试自己新建的临时文档里打字，不碰你已经打开的记事本内容）、防卡死 | 3 分钟 |
| `npm run perf` | 性能测试：正常播放、全部隐藏、全屏时自动隐藏，三种状态各 5 分钟 | 16 分钟 |
| `npm run capture-test` | 截图隐身测试：GDI 截图、Chromium 屏幕采集、Win+Shift+S。每种方式都要"不保护时能截到猫、保护时截不到"才算通过 | 1 分钟 |
| `npm run rapid-interrupt-test` | 快速连续打断（站 → 坐 → 还没切完就站回去），检查猫不会卡住。不动鼠标键盘 | 20 秒 |
| `npm run record` | 把三种衔接方式并排录屏，导出 MP4、GIF 和逐帧对比图 | 30 秒 |
| `npm run gen:clips` | 重新生成测试片段 | 15 秒 |

结果都写在 `results/`（不提交到仓库，报告里引用的数据已经整理进 `docs/验证报告/`）。

**跑测试时请不要碰鼠标和键盘。** 交互测试检测到有人动了鼠标会自动重做这一项（最多 3 次）。
测试用的"探针窗口"是置顶的，这样即使有别的程序的窗口弹出来，穿透的点击也只会落在探针窗口上，不会误点到别的程序。

### 性能测试的要求

- **同一台电脑上不能有其他会话在运行 Electron 程序或素材工厂**，否则数据作废。脚本会每 15 秒检查一次，结果里 `exclusivity.ok` 为 `false` 就说明测试期间有别的 `electron.exe`、`python` 或 `ComfyUI` 在跑。
- 全屏阶段会有一个深色窗口铺满整个屏幕 5 分钟，这是正常的。
- 参数：`--minutes=5`、`--phases=playing,hidden,fullscreen`、`--gpu=`、`--fps=`、`--preload=`、`--res=`、`--bare`（和桌面层参数含义一样）。

报告里的正式数据用的命令：

```bash
npm run perf -- --fps=30 --preload=lazy
npm run perf -- --gpu=default --fps=30 --preload=lazy --phases=playing,hidden
```

## 手动测试步骤

### 台式机交互测试（3440×1440 和 2560×1440，100% 缩放）

按设计方案 D23，只保证 4 种显示配置：笔记本 2880×1800 150%（已测，见报告第 5 节）、台式机 3440×1440 100%、2560×1440 100%、1920×1080 100%（由 1440p 覆盖，不单独测）。台式机的两种配置要在台式机上各跑一次 `npm run interaction-test`。Windows 的分辨率不能由程序安全地自动切换，中间要用户本人切一次。

**给执行的 AI 会话**：除了第 3、6 步的分辨率切换，其余步骤都由你来做；需要用户动手的步骤要先用大白话告诉用户怎么点。

1. **独占检查**：请用户先暂停同一台电脑上的其他会话（特别是会动鼠标的"电脑操作"工具），然后确认没有别的 Electron 或素材工厂在跑：

   ```bash
   tasklist | findstr /i "electron.exe python.exe ComfyUI"
   ```

   有输出就先停下来问用户，不要开测。测试会用 `SendInput` 移动真实鼠标，期间用户**不要碰鼠标和键盘**（大约 3 分钟）。
2. 拉取最新 `main`，在本目录运行 `npm install`。
3. **用户操作**：打开"设置 → 系统 → 屏幕"，在主显示器上选分辨率 **3440×1440**、缩放 **100%**。接着副屏不用拔，测试只在主显示器上进行（D23 已接受这种情况）。
4. 运行 `npm run interaction-test`。终端最后一行会打印"显示缩放 100%：通过 X 项，失败 Y 项"。结果写在 `results/interaction-100pct-<时间戳>.json`，其中 `workArea` 一栏能看出当时的分辨率。
5. 把结果复制到 `docs/验证报告/M0-A-渲染与交互-素材/interaction-3440x1440-100pct.json`。
6. **用户操作**：把主显示器分辨率改成 **2560×1440**，缩放仍是 100%。等屏幕稳定（约 5 秒）。
7. 再运行一次 `npm run interaction-test`，把结果复制到 `docs/验证报告/M0-A-渲染与交互-素材/interaction-2560x1440-100pct.json`。
8. **用户操作**：把分辨率改回 3440×1440。
9. 把两次结果填进报告第 5 节"显示配置"表格和第 9 节，更新"结论速览"里"按每帧点击遮罩判定"那一行。有失败项时，先在报告里如实记录失败项和原始数据，再决定是修原型还是改 ADR-0003，不要重跑到通过为止却不记录失败。然后开 PR，描述里写 `Closes #2`。

如果某一项失败且看起来是被别的程序打扰（比如弹窗、通知），脚本会自动重做该项（最多 3 次）；三次都失败就当成真实失败处理。

### 已取消的手动测试

以下项目按用户决定（2026-10-01，见 PR #17 的 D10、D24 和 ADR-0004）不再做：

- 笔记本 100%、125% 缩放（不在 D23 支持范围内）；
- 微信、QQ、腾讯会议、Teams/Zoom、OBS 的截图和屏幕共享；
- 系统睡眠后的结算（改由 `core/game` 的单元测试模拟时间跳变覆盖，见 #22）。

`npm run capture-test -- --manual` 和托盘里的"显示调试信息"仍然可以用来手动看效果，但不再是验收项。

## 目录

```
assets/clips/        合成测试片段（VP9 透明 WebM，384×384，24fps）和逐帧点击遮罩（96×96，1 位/像素）
scripts/gen-clips.mjs  生成测试片段
scripts/build.mjs      用 esbuild 编译 src/ 到 dist/
src/main/            桌面层主进程：透明置顶窗口、鼠标穿透开关、防卡死、幽灵模式、全屏检测、性能采样
src/renderer/        桌面层渲染进程：PixiJS 视频纹理、三种衔接方式、按点击遮罩命中判定、拖动
src/probe/           探针窗口：放在猫下面的普通窗口（独立进程），记录自己收到的点击和打字
src/shared/          Windows API 绑定（koffi）、测试用控制通道、共享类型
src/tools/           测试脚本
```
