# M0-B 窗口模式小验证

独立验证工程，仅用于 issue #3，不接入桌宠，也不把 proposed ADR 当作正式接口。

## 运行

需要 Windows 桌面、Node.js 24 以上。在本目录运行：

```powershell
npm install
npm start
```

每块显示器有一个透明、置顶、不接收鼠标、不抢焦点的调试窗口。绿线是可用窗口顶边，红线表示窗口快速移动。系统托盘提供暂停 / 恢复、导出采样和退出。启动后请拖动普通窗口，观察顶边是否贴着窗口移动。

```powershell
npm test          # 遮挡、按钮避让、负坐标、DPI 归一化规则
npm run verify    # 真实 Win32 窗口读取、遮挡、坐标往返、快速移动和窗口状态过滤
npm run verify:apps # 六类常见应用的真实窗口移动，结束后恢复布局
npm run measure   # 持续 30 秒，导出轮询开销后自动退出
```

`verify` 会用一个独立进程临时打开重叠测试窗口，以及鼠标穿过层、完全透明层和不支持 DPI 的原生窗口。它移动、最大化、最小化、隐藏、全屏并恢复测试窗口，结束后退出。验证时的线仅来自测试窗口，以免用户的置顶窗口完全挡住测试目标。这不是完整桌面遮挡验收。普通 `start` 和 `measure` 始终计算完整桌面。

`verify:apps` 要求六类应用已经打开，包括资源管理器、Chrome、微信、VS Code、记事本和设置。它临时移动及最大化这些窗口，检查真实边界、最大化识别与读取到的矩形扣除，并恢复位置与最大化状态；找不到任何一种应用时返回非零退出码，不跳过。设置还核对公共标题，避免把其他 UWP 应用当成设置。**这些检查不能证明读取到的按钮位置就是实际按钮位置。** 请先保存工作，测试期间不要手动移动这些窗口。新启动的设置可能仍被系统 cloak，请等窗口显示后再测。

结果在 `results/`（已忽略）：`sample.json`、`verify.json`、`measure.json`、`overlay-<序号>.png`、`fixture-window.png`。原始采样含窗口标题，公开分享前请去除个人信息。截图分别捕获透明调试层和独立测试窗口，不捕获用户窗口内容；不能把它们当作完整桌面最终对齐的照片。提交的报告附有去除私人标题的测量摘要。

## 实现和口径

- `src/main/platform/win/windows.ts` 是本独立工程的系统边界。用 koffi 调用 `EnumWindows` 收集 Z 序窗口句柄，再读取 DWM 真实边界、隐藏状态、按钮边界及窗口 DPI。避免拖动换序时逐个调用 `GetWindow` 导致重复句柄或死循环。
- `verify` 另检查桌面层绘制区的 CSS 尺寸与逻辑视口一致、Win32 外框符合已知测试位置，并在测试窗口频繁换序期间进行 300 次枚举。调试层每次采样后重新置顶，不获取焦点，避免拖动时被活动窗口盖住。Windows 置顶补丁和坐标转换位于 `platform/win/overlay.ts`。
- 隐藏、最小化、cloak 和本进程窗口不参与计算。工具窗口、过小窗口、最大化窗口、全屏窗口、桌面壳窗口不能提供窗口顶边，但仍保留遮挡作用。不按应用名称写特例。
- 分层且鼠标穿过的窗口、能查询到全局 alpha 为 0 的窗口不参与遮挡，`ignoredTransparentWindows` 记录原因。该 M0 策略会忽略可见的鼠标穿过装饰，也不能识别所有逐像素透明情况；M4 必须补充验证。Codex 的透明置顶层曾遮住屏幕右侧约 44%，详见报告。
- 默认过小阈值是 160 × 80 逻辑像素。快速移动阈值是 800 逻辑像素/秒，由真实采样时间和所在显示器缩放计算；`windowDpi` 只用于诊断，避免老程序返回 96 导致倍率错误。阈值只是验证参数，尚不是 M4 的产品决定。
- 所有遮挡计算先用物理像素。绘制使用 Electron 的 `screenToDipRect`，再减去对应调试窗口的逻辑坐标原点。不要把整块桌面的绝对坐标直接除以一个缩放倍率。
- DWM 的按钮坐标相对于 Win32 窗口，因此加 `GetWindowRect` 原点，而不是 DWM 可见边界原点。没有可靠按钮区域时，保守预留右侧 160 逻辑像素，`buttonsFallback` 标记这一退路。
- 遮挡按矩形近似，不识别逐像素透明区域、圆角或特殊自绘按钮。短于 8 逻辑像素的碎线被排除；猫的实际站立宽度、身体上方空间和显示器范围裁剪留给 M4。
- 轮询周期目标 100 ms，实际间隔由单调时钟记录。轮询时间 / CPU 只包住窗口读取及 Win32 查询，不包含几何计算、IPC 和绘制。CPU 百分比按单核容量计算，不是总系统 CPU。
- Windows 进程 CPU 时间粒度约 16 ms，不解读单次 CPU 样本或其 P95；只用长时间 CPU 累计量和单核平均百分比。`pollingMs` 是墙钟耗时，不能直接当作 CPU 时间。
- `sampleToRendererAckMs` 从开始读取到渲染层的下一次动画帧回执，包含读取和 IPC，但不是屏幕实际呈现时间，也不是从用户拖动开始算的延迟。首次绘制可能有较高峰值。
- `commandedMovementToRendererAckMs` 每种缩放下记录五次真实窗口移动到对应新边界的绘制回执，包含测试命令文件接收端最多 50 ms 的等待和正常轮询等待。它仍不是屏幕呈现时间。

## 必须补做的桌面验收

在 Windows 显示设置中分别选择 **100%、125%、150%**，每次运行 `npm run verify`、`npm start`。不要用 Electron 强制缩放参数替代系统 DPI 验收。调整前记录原缩放，测完恢复。

逐一测试资源管理器、Chrome 或 Edge、微信、VS Code、记事本、设置：普通窗口、最大化、最小化、恢复、交叉重叠；拖动时检查调试线和按钮避让。自绘标题栏需要人工确认右侧预留是否足够。多显示器尤其应测试窗口跨越不同缩放的显示器。

性能测量前，停止其他开发会话的 Electron 和素材工厂；不要为了测试关闭用户正在使用的应用。先运行 `measure`，再打开测试窗口跑 `verify`，两者不要同时跑。

参考：[DWM 属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)、[Electron screen](https://www.electronjs.org/docs/latest/api/screen)、[koffi 输出参数](https://koffi.dev/output)。
