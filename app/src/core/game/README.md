# core/game

需要存档的规则，在主进程里运行。管理设置、猫的显示列表和勿扰模式，以及不存档的一键隐藏、开机静默和调试时钟偏移；事件、需求和亲密度等到对应阶段再加。

接口：`src/shared/core-api.ts` 里的 `GameCore`。入口是本目录 `index.ts` 导出的 `createGameCore`。

调用方传入已校验的内容、存档和命令，以及真实时间、本地时区偏移函数。`stateChanged` 表示需要存档，同时一定需要推送快照；只有 `snapshotChanged` 时只推送快照，不写备份。`stageCommands` 按顺序交给桌面层执行，`problems` 是命令被拒绝的中文原因。互动事实不改变存档。

调用方定期调用 `tick(now)`，处理勿扰到期、安静时段切换和开机静默结束。创建时直接清除存档中已到期的勿扰；时间倒退不会复活已经结束的勿扰或开机静默。未到期的计时继续按结束时刻判断。快照不会代替 tick 修改存档。

安静时段按调用方提供的本地时间判断，包含开始、不包含结束，首尾相同表示关闭。三种静音原因按勿扰、安静时段、开机静默的顺序列出。一键隐藏不改变显示列表；召唤时先取消一键隐藏并发送入场，再发送召唤，勿扰保持有效。

调试快进只在 core/game 内累计偏移，安静时段与开机静默按偏移后的时间判断。定时勿扰的结束时刻始终是真实时间，每次快进直接减少同等时长；存档和快照不用再换算，重建后剩余时间不变。隐藏、偏移和开机静默不进存档。

停用或缺失的猫保留在设置、快照和导出的存档中；只向已加载且显示中的猫发送桌面层命令。初始存档、设置补丁、快照和导出状态均不共享内部设置的可变引用。
