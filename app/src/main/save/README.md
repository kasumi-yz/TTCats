# 存档模块（#20）

`SaveStore<T>` 只在主进程使用。每个数据目录只创建一个实例，传入目录、当前版本、状态的 zod schema、默认状态工厂、时钟和中文日志回调。不依赖 Electron，也不认识具体的猫或 `GameState` 字段。

正式应用的数据目录由 #28 的调用方传入 `%APPDATA%\TTCats`；本模块不读取环境变量、不调用系统时钟。`now()` 返回真实时刻的 Unix 毫秒，计时器只负责合并写入。不要把调试台的游戏快进时间当作保存时刻。

## 对外方法

- `load()`：主文件 → 从新到旧的正常备份 → 经 schema 校验的默认状态。返回 `state`、来源 `source`、文件路径 `file`、原保存时间 `savedAt` 和 `readOnly`。读取、迁移和恢复都不会立即改写原件。
- `requestSave(state)`：校验并捕获 JSON 快照，默认 1 秒合并窗口。窗口内的新请求替换待写快照，不把计时器往后推。
- `flush()`：退出前必须调用；立即取消计时器并同步写完最新快照。失败会抛中文错误，调用方应提示用户/记录诊断信息；待写快照保留，可再次调用重试。自动写入失败会记中文日志，下一次请求重新安排写入。
- `loadLatestBackup()`：供 #27 安全模式使用，忽略主文件，按新旧顺序返回第一份能迁移并通过校验的备份；没有正常备份返回 `null`，由安全模式决定下一步。
- `readOnly`：发现更高版本的主存档或备份后，本实例永久禁止写入。可以回退到旧备份或默认状态供查看，但不能覆盖新版数据。

同步读写使写入、备份轮换和退出前强制保存不会互相交错；这是小型状态文件的模块，不适合写入动画素材或其他大文件。

## 文件和迁移

外层为 `{ saveVersion, savedAt, state }`，读取直接使用 #18 定稿的共享 `SaveEnvelopeSchema`。写入时额外检查保存时间为非负有限数。最终状态用调用方传入的 schema 校验。迁移表的键是来源版本，例如 `migrations[1]` 把版本 1 的状态升到版本 2；必须逐版本迁移，不能跳步。迁移失败、缺步骤或最终校验失败时继续尝试备份。

主文件是 `save.json`。写入顺序为：

1. 写 `save.json.tmp`，刷盘并关闭文件。
2. 旧主文件能正常读取时，把其原始内容写到备份临时文件，刷盘并重命名为 `save.backup.<16 位递增序号>.json`。主文件存在但无法校验或迁移时，把原始字节写到另一份临时文件，刷盘并重命名为 `save.invalid.<唯一编号>.json`；保留失败则禁止覆盖主文件。这份原件不参与 5 份备份轮换，也不自动加载或删除，修复迁移后可人工恢复。中文日志会以“已安全写入存档”报告原件副本路径。
3. 备份轮换至最近 5 份，再用同目录重命名替换主文件。序号不依赖保存时间，所以时钟倒退不改变恢复顺序。

读取忽略所有 `.tmp` 文件；替换失败时不会先删除主文件。下次写入会覆盖主存档的遗留临时文件。中断可能留下与主文件内容重复的正常备份，或未完成的原件副本临时文件，但不会把未完成的临时文件当作成功存档。这里验证的是程序中断恢复，未承诺对硬件故障或突然断电的完整保障。

日常写入成功不记日志，写入前重复校验备份也不记录普通损坏或迁移日志；启动读取/安全模式恢复仍报告这些问题和最终来源。发现新版数据、保留原件和自动写入失败仍记录中文日志。

## 验证

在仓库根目录执行 `npm ci`、`npm run check`。专项测试可以执行 `npm test -w app -- src/main/save/save.test.ts`。

主进程、实际 `GameState` 和调试台的接线归 #28；本 issue 不修改启动流程、共享接口或面板。
