# main

主进程：窗口管理、托盘、core/game、存档、自动更新、日志和诊断、崩溃恢复。

和操作系统打交道的代码（koffi、`process.platform` 判断等）只能放在 `platform/<os>/` 下，
ESLint 会拦下其他地方的用法（硬性规则 3）。

## M1 主进程接线（#28）

入口按单实例锁、日志、存档、内容、core/game、桌面层、托盘的顺序启动。面板按需创建。
正式数据和日志分别在 `%APPDATA%/TTCats/save.json`、`%APPDATA%/TTCats/logs/`。

在仓库根目录运行 `npm run build` 后，使用 `npx electron app --test-content --settings`
打开三只合成测试猫及设置窗口。开发时在 `app/` 下运行
`npm run dev -- -- --test-content --settings`。`--test-content` 只在未打包时有效；
不用该参数时按内容模块约定读取正式内容（或开发环境的 `TTCATS_CONTENT_DIR`）。
当前正式内容尚缺真实片段，被内容校验停用是预期结果。

隐藏快捷键 **Ctrl+Shift+F10** 打开调试台。托盘可召唤、切换显示、切换截图显示、打开设置或退出。
右键菜单绑定不抢焦点的桌面层窗口；主动选择资料卡后才打开普通面板。

M2（#66）每秒以真实时间推进 GameCore.tick，按 stateChanged 存档、snapshotChanged 推送快照。
安静时段变化只推快照；启动清除过期勿扰时只写回有变化的存档，避免轮换无变化的备份。
快进偏移由 core/game 管理，主进程始终传真实时间。
窗口关闭后托盘继续运行，退出前完成排队的保存；保存失败可选择重试或不保存直接退出（#49）。

每个桌面层只接一个恢复控制器；显示配置变化也复用同一窗口，不清空重试额度。
恢复失败或第四次崩溃时立即锁定隐藏并停止提交正常状态。
安全模式备份先读入内存，再完成原 SaveStore 排队的正常写入；重新创建 core/game、过滤内容目录，
快照版本仍递增。之后面板修改只作用于本次内存状态，退出不把回退状态写进正常存档。
没有可靠猫 id 的错误归属消息，因此保守停用当前显示且已加载的包；保留中文名字、原始文件和显示偏好。
面板重新加载以取得过滤后的内容和停用原因。

`TTCATS_TEST_APP_DATA` 是未打包应用的自动测试隔离选项，不读取或改写用户正式存档。
测试不会把它当成面向用户的设置。

## 主进程的模块划分（#53、#98）

`index.ts` 只按顺序接线，不写功能逻辑。启动顺序：单实例锁 → 日志 → 存档和内容（`game-data.ts`）
→ 面板窗口 → 程序状态 → 游戏会话 → 各功能 → IPC → 桌面层 → 托盘 → 各功能的启动步骤 → 退出接线。

- 面板窗口及登记窗口的集合：`panel-windows.ts`；托盘：`tray-menu.ts`；猫的右键菜单：`cat-menu.ts`；
  IPC：`ipc-router.ts`；保存失败的选择与退出状态：`shutdown.ts`。
- `game-commands.ts`：游戏命令的桌面层转发、托盘刷新和召唤坐标换算。
- 只有一份、由入口创建后传给需要的模块：游戏会话（`game-session.ts`）、程序状态（`app-status.ts`）、
  每秒推进游戏的计时器（`game-ticker.ts`）。功能模块不要自己再建一份。
- 各功能的接线：桌面层和崩溃恢复 `overlay/feature.ts`、开机启动 `autostart/`、一键隐藏快捷键
  `hide-all-shortcut.ts`、勿扰菜单 `do-not-disturb-menu.ts`、拍照 `photo/`、自动更新 `updater/`、
  诊断导出 `diagnostics/`、调试台快捷键 `debug-shortcut.ts`、再次启动和关窗监听 `app-listeners.ts`。

### 加一个新功能

1. 在自己的文件（或目录）里导出 `createXxxFeature(deps)`，返回一个 `MainFeature`（`features.ts`），
   只填用得到的字段，末尾写 `satisfies MainFeature`：
   - `onSnapshot(snapshot)`：快照变化后调用，在面板收到快照之后、托盘刷新之前。
   - `menuSection`：托盘菜单段（见下）。
   - `mainCommands`：本功能负责的 MainCommand 处理函数（见下）。
   - `start()`：桌面层和托盘都就绪后调用，例如注册全局快捷键、启动定时器、挂 `app` 监听器。
   - `dispose()`：退出清理。
     需要的东西（会话、程序状态、`updateTray`、`stopping`、`report`、打开面板等）从 `deps` 传进来，
     取值用回调（如 `() => session.safeMode`），不要在模块里缓存会变的状态。
     只在创建时需要做一次的事（如按存档同步一次系统设置）在 `createXxxFeature` 里直接做。
2. 在 `index.ts` 的 `combineFeatures([...])` 里加一行。数组顺序就是快照通知、菜单段、启动、
   退出清理的顺序；放在和它相关的功能旁边，不要改别人的行。
3. 写单元测试，并在调试台能手动触发（硬性规则 5）。

不要为了凑齐字段写空函数，也不要在 `index.ts` 里写功能自己的判断。多个 PR 同时往数组里加行时，
合并包里保留各行、按设计方案核对顺序即可。

### 托盘菜单段

`TrayMenuSection` 接收当前的 `TrayMenuContext`（内容、设置、安全模式、游戏命令、召唤、打开面板、退出），
返回 Electron 菜单项数组。托盘每次刷新都重新取快照，按顺序拼：猫的召唤和显示 → 各功能的菜单段
（勿扰、截图显示、拍照、更新……）→ 分隔线与设置、退出。需要分隔线时由自己的段显式返回。
菜单文字用共享中文语言文件；安全模式下是否可用在自己的段里决定。
需要快照之外的状态时，在自己的模块里通过闭包读，不要扩充 `TrayMenuContext`。
下载状态、全屏隐藏等非快照状态变化时，调用传进来的 `updateTray` 刷新。
游戏命令无论成功、被拒绝还是抛错，命令处理函数都会刷新托盘，避免复选框显示错误。

### MainCommand 处理函数

游戏命令仍经 `game-commands.ts` 的 `command` 交给 `core/game`，事实只接收登记桌面层的主框架，
快照和内容查询只接收登记窗口的主框架。退出期间或安全模式下不接收事实。

MainCommand 由负责它的功能在 `mainCommands` 里按消息的 `type` 提供。`combineFeatures`
在编译期检查每种 MainCommand 恰好由一个功能负责：漏了会报 `missingMainCommands`，
重复会报 `duplicateMainCommands`，属性类型里写着是哪个命令。
处理函数自己检查安全模式和退出阶段是否允许执行。同步异常和返回的 `Promise<void>`
拒绝由路由统一交给 `report` 写日志；异步处理函数必须返回该 Promise。

新增共享消息必须先走接口变更 issue/PR；消息定稿后，同步更新 `messages.ts` 的校验，
双向类型断言会拦住漏项。接口先合并、功能尚未接入时，按 #52 为已经定稿的 MainCommand
显式注册拒绝处理函数：调用 `report(zh.interfaces.commandNotReady(message.type))`，
不改变状态、不启动任务。功能 issue 实现后换成真正的处理函数。

已有 `debug/crashOverlay` 沿用恢复模块的独立监听器，再交给上述注册函数，
保持原来的崩溃调试接收规则。其余命令通过完整 schema 校验后分发，
拒绝消息的日志继续包含消息类型和字段路径。`registerIpcRoutes` 返回清理函数，
退出时移除命令、事实及查询的所有接线。

### 退出顺序

`attachShutdown` 先存档（失败可重试或不保存直接退出），再同步执行清理步骤：
各功能的 `dispose`（按登记顺序）→ 移除 IPC → 托盘 → 内容协议 → 面板窗口；
然后等桌面层窗口释放（`overlay/feature.ts` 的 `disposeWindow`），释放主日志，
最后交给自动更新的 `finishQuit`：有下载好的更新才安装，否则正常退出。
`dispose` 里不要另建 `before-quit` 监听器，也不要吞掉异常。

## M2 防打扰接线（#66）

托盘的召唤子菜单首项是“全部”；勿扰位于猫的显示菜单之后、截图显示之前。
定时勿扰显示真实结束时刻；直到关闭的勿扰可跨重启。一键隐藏不存档，快进偏移也不存档。
设置的一键隐藏快捷键变化后释放旧键并注册新键，失败记日志并通过 AppStatus 通知面板；
显示桌面层使用 showInactive，不主动改变前台焦点。退出停止推进并释放快捷键。

全屏模拟与系统查询结果取并集；停止模拟后回到系统判断。只有全屏结束并恢复显示时，
才在 paused:false 后发送 cat/entrance。启动与崩溃重载复用 StageCore 自带的依次入场。
单只猫的显示变化交给 stage 处理出入场；最后一只猫出场期间继续绘制，通过已有的画面报告
确认猫已走完，再隐藏、暂停桌面层。一键隐藏则立即暂停，不等出场。
等待最后一只猫出场时，主进程暂时打开已有的画面报告，出场后恢复调试台原本的报告开关，
遵守“桌面层只有收到 enabled:true 才报告”的接口约定。

app-status.ts 持有一份独立、递增版本的程序状态，getAppStatus 查询采用与快照相同的发送方检查，
推送只到面板窗口。#65 可用 update 更新 displays/overlayDisplayId，#68 可更新 update，
在它们接入前按 #52 交接保留空显示器列表与 unsupported 更新状态。

新增冒烟覆盖出入场、召唤全部、勿扰睡觉/快进结束/重启保留、快捷键换键/失败、
一键隐藏恢复与重启清零、模拟和受控系统全屏结束后入场、崩溃重载入场。
全屏查询及快捷键失败可在原生边界受控；真实全屏识别和前台焦点另做本机桌面验证。

## 验证边界

`npm run test:smoke` 从 `app/e2e/launch.js` 加载正式构建入口，使用临时数据目录。
覆盖桥与初始快照、三只测试猫、托盘开关、设置退出重启、调试台全部命令、右键菜单和资料卡、
双窗口错误日志、四次真实渲染崩溃、备份/默认回退、慢加载中再次崩溃、快速连点及安全模式存档保护。
调试台通过已注册的 Ctrl+Shift+F10 回调打开；默认测试核对原生注册成功。
本机多个会话并行测试时，可显式设置 `TTCATS_SMOKE_CONTROL_SHORTCUTS=1`，只在测试入口
控制快捷键注册、查询和注销，避免各会话争抢同一按键；正式入口不读取此选项。
`npx tsx app/e2e/desktop-wiring.ts` 从正式入口验证真实按键切换隐藏、输入窗口保持焦点、
真实全屏窗口关闭后重新入场；结果写入 `app/test-results/native-m2-wiring.json`。

测试保留真实窗口、托盘、preload、IPC、core、渲染和磁盘保存；原生弹出菜单和提示框由测试观察器捕获并调用菜单项。
全屏状态仅在系统查询边界受控，避免 CI 或当前桌面的忙碌状态让测试一直隐藏。
因此这里验证的是正式隐藏/恢复逻辑与菜单接线，不声称完成系统鼠标命中、不抢焦点或真实全屏识别验收。
其他真实桌面交互、D23 多配置、性能和连续运行验收属于 #29 / #69。

`tray-menu.test.ts` 和 `ipc-router.test.ts` 用假的 Electron 对象验证菜单段顺序、
安全模式变灰、快照刷新、游戏/主进程命令分流、未知窗口与子框架拒绝、事实与查询及清理。
`shutdown.test.ts` 验证清理顺序、重复退出、保存失败重试或放弃，以及桌面层释放失败的收尾。
原有冒烟测试及其断言保持不变。

额外执行 `npx tsx app/src/main/recovery/desktop.verify.ts` 覆盖恢复模块五个真实 Electron 场景：
四次崩溃、无响应、慢加载期间先 reject 后 gone、快速重复崩溃后后续命令有效、12 秒慢加载不误杀。

构建配置除加入桌面 HTML 外，将 PixiJS 独立分包：默认分包中 Pixi 动态导入反向依赖带顶层 await 的桌面入口，
会互相等待并留下空桌面。两项构建修改均经 #28 用户明确批准。依赖版本未改变。
